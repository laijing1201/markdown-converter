## 三、技术方案

- **架构**：Supabase（Postgres + Auth/GoTrue + Edge Functions + RLS）。理由：0001 起即按此建模，认证/会话/密码哈希由 GoTrue 承担（bcrypt、会话 7 天、httpOnly 存储由 supabase-js 管理），自定义 Edge Functions 只做「计次执法 + 管理端 service_role 通道」，攻击面最小。
- **管理后台**：独立入口 `admin.html`（同仓同构建、独立会话 `admin_sessions`），前端仅展示与确认，所有数据经 `admin-api`（动作路由 + 权限矩阵 + 审计）。
- **邮件**：GoTrue 原生负责注册验证/忘记密码系统邮件；管理端重发/重置经 Resend 发信并落 `email_logs`。未配置 `RESEND_API_KEY` 时如实记失败（不伪造发送）。

## 七、管理员使用手册（要点版，终稿随 M4）

1. **登录**：`/admin.html` → 邮箱+密码（+TOTP）。会话 2 小时无操作自动过期。
2. **仪表盘**：用户总数/近 7 日新增/待验证/禁用/匿名与注册转换次数/转化率/历史总数/邮件量与失败数/系统状态。
3. **用户管理**：搜索、状态筛选；禁用（同时强制下线）、启用、强制下线、重置密码（发邮件）、重发验证；删除与数据导出仅超管可见。
4. **历史记录**：按标题/用户筛选；元数据全员可见；「查看正文」仅超管且每次写审计；删除为软删除；「按用户清空」仅超管。
5. **系统配置**：免费次数、IP 放行、历史保留、开放注册、强制验证、会话天数、维护模式、公告；保存即生效并写审计。
6. **审计日志**：只读，记录管理员 ID、动作、对象、详情、IP 哈希；数据库层不可删改。
7. **2FA 绑定**：管理员在 Supabase Auth MFA API 注册 TOTP（后台「安全设置」页 M3 交付前可用 Supabase Dashboard 完成）。
